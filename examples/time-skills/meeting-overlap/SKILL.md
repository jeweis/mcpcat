# 跨时区会议安排

明确参会地点、会议日期、基准时区、时长和可用时段。用户没有特别约定时可假设工作日 09:00–18:00、午休 12:00–13:00，并在结果中说明；不要猜测节假日或个人日历。

通过当前连接中的 `get_current_time` 确定基准地日期，将“今天/明天”解析成明确日期。发现工具后再使用 `convert_time`，以实际 schema 为准。

重要限制：部分 Time MCP 的 `convert_time` 只有 HH:MM，没有日期参数，实际按来源时区的今天换算。只能把这种结果用于该来源日期，不可拿今天的偏移推算未来会议或跨夏令时日期。若需要其他日期，使用客户端已有的带 IANA 时区数据库的日期计算能力，或明确告知当前工具不足；不得伪造日期参数或声称服务器验证过未来日期。

将各地可用时段换算到同一时间轴求交集，保证完整会议时长都落入交集，并核对各地结束日期。推荐最多三个时段，列出双方完整日期、开始/结束时间、IANA 时区和 UTC 偏移。没有交集就解释冲突，询问哪一方可放宽时间，不默认安排加班。

只给安排建议，不创建日历事件、不发送邀请。本 Skill 不含服务器脚本。
