# 远程读取 Skills

本页描述本次已实现并验收的升级代码，已部署至本机 Docker；不代表公共 npm/Docker 已发布新版。独立端点、服务/Catalog 远程读取、模式生成和前端接入均可用，第三方 Host 的激活/交互边界仍见客户端矩阵。作者准备内容请参阅 [Skill 作者指南](skill-authors.md)，程序升级/回退见 [完整恢复流程](../maintainer/upgrade-recovery-drill.md)，验收范围见[最终验收](../maintainer/mcp-final-acceptance.md)。

## 两种使用方式

- **本地安装**：下载 ZIP 或使用 [mcpcat CLI](cli.md) 安装到 Agent 目录，保持已有使用方式。
- **远程读取**：客户端连接 mcpcat 的 Skills MCP 端点，通过官方 Skills 扩展发现指令、按需取得文件。不会自动安装到客户端目录，也不会让服务器执行 Skill 脚本。

能读取普通 MCP Resources 不等于能自动激活远程 Skills。客户端必须支持对应扩展、完整性验证及用户信任审批；没有这些能力时继续使用 ZIP/CLI。本项目尚不承诺任何特定第三方 Agent 已完成远程激活验收。

## 独立端点固定提供

使用 WRITE 身份访问 `GET /api/admin/settings/skills-mcp` 查看配置和实际状态。通过 `PUT` 保存，例如：

```json
{
  "path_name": "skills",
  "require_auth": true,
  "page_size": 25
}
```

无需启用开关；默认路径为 `/mcp/skills`，默认需要 READ Key。确认响应中的 `ready=true`；`restart_required=true` 表示路径或分页设置尚需重启，不能仅凭保存成功向用户发放地址。升级时若旧服务占用默认地址，系统自动持久化避让到 `mcpcat-skills`（必要时加数字后缀），原服务地址不变；以实际状态和接入信息为准。手动改路径不能占用其他入口。

旧 `enabled`、`independent_enabled` 和环境变量 `MCPCAT_SKILLS_ENABLED` 兼容忽略，不再关闭平台能力。固定提供分发能力不等于自动发布内容；旧 local-only 包不会自动增加 remote。更换路径会使旧入口不可用，重启后才挂载新路径，旧路由卸载前不能交给其他服务。限制具体内容使用资源撤回与权限控制。

## 发布并连接

管理员可向 `POST /api/skill-variants/generate/service/<服务名>` 或 `POST /api/skill-variants/generate/catalog` 提交模式：

```json
{ "selection": "both" }
```

支持 local、remote、both，默认 local；生成后仍需审核发布。both 使用同一工具快照，不能只发布尚未完成的一半。旧 `/api/skills` 生成接口仍默认本地版，原 CLI 不需要升级或切换模式。remote-only 不要求设置对外地址，也不改变旧本地下载的 latest。

上传 Skill 时选择 remote 或 both，审核对应文件和执行前提，再发布完整版本。历史已冻结的上传 Skill 要新增 remote 时，创建更高版本草稿并共享原文件；不会覆盖旧 ZIP。普通 MCP 生成 Skill 的 remote 指令需要专用生成模板，不应直接复用 mcporter 本地调用说明。

通过 `/api/skill-variants/<slug>/connections` 获取就绪地址和当前认证头；客户端中配置该地址与 READ Key，凭证通过客户端安全输入/存储提供。不要将 API Key 写进 Skill 文件、URL 查询参数、脚本或日志。

独立端点只提供不依赖该端点 MCP 工具的指令、参考及客户本地脚本。它不提供执行脚本的工具，也不能仅通过此连接调用其他 MCP 服务。脚本需要客户端取得文件后在本地 Agent 环境执行；不具备文件取得/执行能力的客户端使用 ZIP/CLI。

依赖服务工具的内容明确绑定服务端点；跨服务搜索工作流绑定 Catalog。连接对应服务或 Catalog 后，客户端读取该作用域的 Skill，不会取得其他端点的执行说明。声明的工具不在当前目录中或来源停止时，内容会隐藏；服务重启保留原 URI，删除后同名重建视为新来源，不能沿用旧发布审核。独立入口与来源扩展均固定提供；客户端仍需遵守协议的逐请求 opt-in。

URI 固定实例、端点和版本。新版本发布不会把旧 URI 替换成新内容；撤销或归档会拒绝旧 URI 的新请求。服务器不能远程删除客户端已经缓存或安装的文件。

匿名读取要求端点 `require_auth=false` **并且**该版本发布时明确审核 `remote_public=true`。默认保持认证；不要为了省去客户端 Key 配置而公开含私有信息的 Skill。

## 管理界面接入说明（升级代码）

Skills 详情先选择固定版本，再选择“本地安装”或“远程使用 / 端点绑定”。远程面板会向服务端检查发布、来源、工具依赖、端点就绪与制品状态，通过后才显示可复制地址。状态只是最近一次检查结果，连接时还会校验权限；资源或服务状态改变后可点“重新检查远程端点”。

认证说明只显示头名称和 `<YOUR_READ_API_KEY>` 占位符，复制地址不包含真实凭证。即使端点本身关闭认证，未经公开审核的内容仍需要 READ Key；界面不会误提示私有内容可匿名读取。

旧 local-only 版本仍保留 ZIP/CLI 入口。管理员可选择远程模式生成更高版本；对于已冻结的上传内容，可以确认独立端点适用性后输入更高版本，共享原文件为双模式草稿，不覆盖或改写原 ZIP。如果指令依赖来源 MCP 工具，不应把它当作独立端点内容；使用具有对应绑定的上传/生成流程。草稿仍须审核发布，上传文件不会在服务器执行。

本节描述升级代码的界面行为，Web 构建同步、双模式与旧下载已在隔离部署验收，见 [Web 证据](../maintainer/skills-ui-design.md)；不要据此认为已发布的 1.0.1 安装已经包含这些入口，也不等同于第三方 Agent 自动激活已通过。

## 上传普通 Skill（升级界面）

在 Skills 中选择“上传 Skill”，将一个 Skill 文件夹或 ZIP 拖入统一区域；也可以点击“选择文件…”后选择“选择文件夹”或“选择 ZIP 文件”。每次只接收一个 Skill，不接受多个混合条目。目录根部须有 `SKILL.md`，目录名使用小写字母、数字和连字符，且与 frontmatter 的 `name` 一致。

文件夹在浏览器本地读取并打包，不执行其中的文件。查看清单和排除项，勾选“已检查文件清单与排除项，确认不含秘密”，再填写版本与变更说明并上传。确认上传前不会将文件发送到服务器。默认跳过 `.git`、`node_modules`、虚拟环境、缓存、`.env`、常见私钥及凭证配置；`.env.example` 等模板保留。这不是完整的秘密检测，仍需自行检查；如默认排除影响必要文件，请整理目录或自行准备 ZIP。ZIP 原样提交，不自动删除其中的内容。

目录选择支持最多 512 文件、16 MiB 总内容和 10 MiB 单文件；ZIP 最大 20 MiB，服务端另有完整校验且可能配置更严格限制。不能选择文件夹的浏览器可继续使用 ZIP。取消、重选或关闭不会自动上传、发布或执行内容。

默认“本地安装”保留旧上传接口；选择“远程使用”或“两种方式”时，还需选择独立端点、当前运行的 MCP 服务或已启用的 Catalog，并确认内容适用性与客户本地执行前提。已停止或被删除的服务不能提交为绑定，服务端会在提交时再次检查。

上传不会把原指令转换成另一套调用说明，也不会执行脚本。两种方式共用同一份上传文件；如指令需要修改，请由作者准备新版本。独立端点不提供来源 MCP 工具；服务或 Catalog 绑定也不会自动接入其他 MCP 服务。

上传完成只创建草稿，并显示校验过的 SHA、文件和脚本清单。进入草稿详情，查看各文件，再审核发布；失败可重试，不覆盖已有版本。remote-only 不会进入旧 CLI 的 local 列表，“两种方式”则继续保留原本的本地下载安装入口。

## 协议范围

现代端点实现 `skills/list`、`skills/get`、Resources 文件读取和逐文件 SHA/size，并声明 `directoryRead`：通过 `resources/directory/read` 分页查看 Skill 根目录及内部目录的直接子项。目录 URI 不加尾斜线；目录列表不执行脚本，也不代替文件读取及摘要验证。测试台检测到该能力后显示“读取目录”入口。legacy 客户端仍可读取普通资源，但不能据此视为支持远程 Skills 激活。参见 [官方 Skills 规范](https://modelcontextprotocol.io/extensions/skills/overview)。

### 已验证的客户端范围

2026-10-15 使用官方 Inspector CLI 2.11.0，在现代协议与显式 Skills opt-in 配置下，通过分页发现、直接 get 和全部文件 SHA/size 校验。Inspector 2.6.0 的现代响应解析没有通过，不能按其宣传支持直接推断互通。检查器通过只证明发现/读取，不等于 Agent 已激活指令或会执行脚本。

mcporter 和 mcpcat CLI 继续服务于本地安装/调用流程；未验证远程激活的 Agent 继续使用 ZIP/CLI。具体固定版本、限制及复现方式见 [Skills 验收与客户端矩阵](../maintainer/skills-protocol-verification.md)。

### 旧客户端连接与空闲恢复

网关与上游分别协商协议，旧 MCP 客户端可以访问现代 HTTP 上游，现代客户端也可以经网关访问旧 SSE 上游。这不代表旧客户端具备远程 Skills 或 Apps 渲染能力。

服务端默认 `MCPCAT_MCP_HTTP_SESSION_IDLE_TIMEOUT=0`，旧 HTTP 会话不因空闲期限失效。管理员可以设置正数秒数以限制空闲会话；持续 GET 等在途连接可能使会话保持活跃，该值不是最长连接寿命。

有限空闲期限触发、网关重启或连接失效后，客户端应重新连接并完成握手，不能继续使用旧 session id。网关不会自动重放失败的业务动作；对于可能写入或产生费用的操作，先确认原动作是否已执行，再由用户决定是否重新提交。现代连接的健康判断不要求客户端发送旧式 ping 或取得 session id。
