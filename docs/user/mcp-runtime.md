# MCP 运行管理与通用启动诊断

使用管理员（WRITE）身份打开左侧 **运行管理**，选择 MCP 服务。
测试台失败时也可从诊断日志进入运行管理。

## 查看失败原因

每次连接有独立尝试编号，记录准备、启动、discover、initialize、就绪或请求阶段。
本地进程报告真实退出码；同一尝试的 stderr、分类解释和协议异常可以关联查看。
平台区分依赖缺失、安装缓存、认证、DNS、TLS、网络、HTTP 错误和未知断连。
没有足够证据时保留“原因未确认”，不会把 Connection closed 一律解释成网络问题。
HTTP 来源会在 SDK 折叠错误前记录状态码，不收集请求认证头或响应正文。

服务显示 running 表示平台入口运行，不等同于上游已就绪；应同时查看协议验证结果。
Ping 成功只代表 ICMP 有回应，不能证明数据库端口、HTTPS 或 MCP 协议可用。

## 本地依赖环境

- `npx`：默认使用该服务、配置和工具链对应的独立 npm 缓存修订。
- `uvx` / `uv tool run`：默认使用独立 uv 缓存修订。
- 原生 Python、Node、二进制命令：记录生命周期和协议；不复制或自动安装其全局依赖。
- 远程 HTTP/SSE：记录协议及错误；上游机器的依赖仍由远程服务维护者管理。

修订存储于数据库同级的 `runtime/` 目录；默认是 `.mcpcat/runtime/`，部署时应随数据卷保留。
清单只包含版本、状态与带密钥配置摘要，不保存原始参数、环境变量或密钥。
共享的是缓存和准备结果，每个连接仍有独立进程、协议会话与用户回调。
缓存隔离不是操作系统沙箱，MCP 程序仍使用应用系统用户的权限。

协议验证成功后，托管包缓存通过包管理器离线复用，减少依赖漂移。
显式缓存路径、刷新选项或外部管理模式保留用户意图。
页面区分观察到的 **活动依赖版本** 和 **缓存版本清单**；后者可能包含多版本，
不是单一活动环境的锁文件。快照最多 200 项，不包含全部系统库。
活动环境定位依赖 Linux 进程信息；无法定位时显示缓存清单，不推测实际版本。

点击 **创建新环境修订**：后续连接使用空缓存重新准备，正在进行的请求不被重放，旧缓存保留。
回滚只能选择同一配置和工具链下已验证的历史修订；配置、镜像或全局系统库的回滚不是此操作。
旧修订会保留以供回滚，需维护者按磁盘容量管理，平台不自动删除可能仍被连接使用的目录。

高级配置可使用 `environment_mode: "external"` 保留外部缓存管理，不注入平台缓存路径。

## 协议与有限恢复

默认 `protocol_mode: "auto"` 使用 FastMCP 协商新旧协议。托管环境记录成功的旧协议，
后续同修订直接使用传统初始化；刷新修订后重新探测。
高级配置可设 `legacy` 强制传统初始化，或 `2026-07-28` 固定当前现代协议。

只在初始化尚未就绪时允许一次明确恢复：

1. discover 收到 RPC 连接关闭，且没有依赖、认证、网络等致命证据时，使用新连接回退 legacy。
2. 可识别的 uv 工具因 `mcp.server.fastmcp` 旧导入失败，且没有显式依赖约束时，
   尝试在其独立环境补充 `mcp<2`。这不限制于 mcpdoc，也不改动 MCPCat 的 SDK。
3. 托管 npm/uv 缓存出现 ENOTEMPTY 或 EINTEGRITY 时，保留失败缓存并创建新修订重试。

其他模块缺失、驱动缺失、凭证错误和网络问题会给出诊断，不盲目降级或关闭证书校验。
业务工具调用不自动重放。`startup_compatibility: "off"` 可关闭自动兼容恢复；诊断仍保留。
