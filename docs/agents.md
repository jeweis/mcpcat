# mcpcat 文档维护规范

本文件约束 `docs/` 下的对外文档维护方式，供维护者和自动化 Agent 在修改功能时共同遵循。

## 目录与受众

- `docs/README.md` 是文档索引。
- `docs/user/` 面向安装、使用和排障 mcpcat 的最终用户。
- 面向维护者的发布、架构或内部验收资料应放在明确的维护者目录，避免混入用户操作流程。
- 每个文档只解决一个主要主题；新增文档后必须更新最近一级索引。

## 事实来源

- CLI 命令、选项和环境变量以 `cli/src/cli.ts`、`cli/src/args.ts` 的当前实现为准。
- npm 包名、Node.js 要求和版本以 `cli/package.json` 为准。
- Agent ID 与默认目录以 `cli/src/agents/` 的适配器实现和测试为准。
- 服务端 API、配置和生成器兼容信息以对应后端代码、Schema 与测试为准。
- 文档与实现不一致时，先核实预期行为；不得仅为了让文档成立而虚构尚未实现的能力。

## 写作规则

- 默认使用简体中文，命令、代码标识符和产品专有名词保持原文。
- 面向结果写作：先给可复制的最短成功路径，再解释选项、安全和排障。
- Shell 示例使用 `bash` 代码块，使用可识别的占位符，不写入真实域名凭证或个人路径。
- 命令、文件名、环境变量和短路径使用反引号。
- 标题层级连续，表格需要表头，链接文字要说明目标内容。
- 仓库内链接优先使用相对路径；需要从前端直接打开的公开文档使用稳定 GitHub `main` 分支 URL。

## 安全要求

- 任何文档、截图、示例输出和测试数据都不得包含真实 API Key、OAuth Token、client secret、Cookie 或私有连接信息。
- API Key 示例统一使用 `<由安全存储注入>` 一类明显占位符。
- 不建议通过命令参数传递秘密；优先描述隐藏输入、系统 Keychain 或 CI secret 环境变量。
- 涉及 HTTP、权限、删除、覆盖、发布和回滚时，必须明确风险或恢复方式。

## 变更同步

出现以下变化时，同一个 Pull Request 必须更新相关文档：

- CLI 命令、选项、默认值、错误处理、环境变量或安装要求变化。
- npm 包名、Node.js、mcporter 或 Agent 兼容范围变化。
- Agent 的检测方式、ID、user/project Scope 目录变化。
- Registry、认证头、连接流程、Skill 安装或生命周期语义变化。
- 前端文档入口或 GitHub 文档路径变化。

CLI 用户文档的规范入口是 `docs/user/cli.md`。`cli/README.md` 可以保留开发、打包和发布者内容，但用户用法不得与该文档冲突。

## 提交前检查

1. 对照真实 `--help` 和相关测试检查全部命令示例。
2. 搜索文档中的版本号、包名、URL 和目录，确认没有过期值。
3. 检查所有相对链接和前端 GitHub 外链。
4. 搜索疑似秘密，确保示例只包含占位符。
5. 对涉及平台差异的内容至少核对 Windows、macOS 和 Linux 行为。
6. 确认新增文档已加入索引，且功能变更已同步 OpenSpec 或对应设计记录。
